# DataPaper 用户模块首版

日期：2026-10-03。交付范围为现有网页的本地可运行首版；没有发布私有线上站点，也没有接入邮件服务。

## 使用方法

1. 按原方式打开“启动网页.bat”，访问 http://127.0.0.1:3000/。
2. 点击右上角“登录 / 注册”。注册填写邮箱、昵称及两次密码，研究方向可在登录后补充。首版不发送验证邮件。
3. 登录后加入文献、编辑笔记，停止输入约 0.8 秒后自动同步到服务器。关闭详情不影响保存；显示“尚未同步”时不要关闭网页。
4. 侧栏“我的文献库”管理收藏并导出，“最近阅读”显示最近打开的 100 篇。右上角账号面板可以编辑资料、修改密码、清空阅读记录或退出。
5. 登录后如发现浏览器中原有清单，可点击“导入本地文献”。先核对目标邮箱、收藏数、笔记数和冲突数，再确认导入。此操作保留原本地数据；相同条目可安全重试。

用户库由服务器持久保存。在同一服务地址用另一浏览器登录同一个账号可恢复收藏与笔记。本机地址不能供远程设备访问；公网跨设备使用仍需部署后端和持久存储。

## 保存与冲突规则

- 游客使用既有 `datapaper-workspace-v1` 浏览器存储，不强制登录。
- 登录后使用账号数据，未确认前不自动合并游客清单。退出后回到原游客清单。
- 每条笔记具有版本号。两处编辑冲突时，保留当前编辑并展示服务器版本，可以合并两版或使用服务器版本。清空笔记也会增加版本，防止旧设备恢复被清空的内容。
- 同步中断时草稿留在当前页面，可重试或导出 JSON 备份；离开页面会触发浏览器的未保存提示。首版不承诺关闭页面、浏览器崩溃或强制刷新后的草稿恢复。
- 账号切换会清理当前显示的私人数据。尚未同步的旧账号草稿只在当前页面内存中保留，重新登录原账号后才能继续同步，不会写入新账号。
- 导入按条目事务处理，并保存导入摘要；重复提交不重复拼接笔记，途中失败后可继续重试。不同笔记保留两个版本；合并超过 20000 字时拒绝该条目，原记录保留。
- 文献不在最新目录时，账号库中的文献快照仍可显示。存储侧使用原有 DOI/URL/标题前缀标识，网页通过文献快照映射到既有浏览器标识。

## 实现位置

- `research/accounts.py`：JSON 账户接口、CSRF、身份校验、参数检查。
- `research/account_store.py`：数据库增量建表、可撤销会话、笔记版本、导入幂等、登录限流。
- `app.py`：接入账户接口；旧网页登录和小程序 token 随密码修改失效；旧兼容登录接口共用限流。
- `site/app/api/account/[...path]/route.ts`：同源代理，转发会话 Cookie，校验写请求来源，禁止个人响应缓存。
- `site/app/lib/use-account-library.ts`：账号状态、同步队列、草稿、跨标签页身份刷新、阅读记录。
- `site/app/lib/account-model.ts`：旧/新文献标识映射、导入条目和冲突文本。
- `site/app/components/AccountPanel.tsx`：注册、登录、资料、密码和导入确认界面。

新增表为 `account_sessions`、`account_notes`、`account_imports`、`account_rate_limits`；原有 `users`、`user_favorites`、`user_reading_history` 保留。首版只增加表，不删除或重建旧数据。账号身份由服务端会话确认，客户端的账号标记仅用来阻止跨标签页误写，不能用来授权访问其他用户。

## 验证

自动化验证使用临时用户数据库，不访问付费模型、不发送邮件：

```powershell
python -X utf8 -m unittest discover -s tests -v
cd site
npm test
npm run typecheck
npm run lint
npm run build
```

账户专项覆盖：旧账号收藏兼容、注册登录、资料更新、退出重登、两账号隔离、CSRF、账号错配、会话重放、改密码后的多设备失效、笔记并发冲突和清空版本、导入冲突保留与重复提交、登录限流。

结果：52 项 Python 测试、16 项网页测试、TypeScript 检查、ESLint 与网页构建均通过。

实际网页验收使用专门的测试账号，验证注册、收藏与笔记、刷新恢复、阅读记录、资料保存、多设备冲突及合并、服务中断后保留草稿并重试，以及跨标签页同步退出。本地清单导入确认页已经检查；事务导入和重复提交由隔离接口测试验证，未将原浏览器清单导入临时账号。验收账号已清理，原本地清单保留。

## 上线边界

- 当前验收以 SQLite 本地用户库为准。MariaDB 适配代码沿用同一用户库，但本轮没有可用的独立 MariaDB 测试实例，不将其视为已验收的生产部署。
- 邮箱验证、忘记密码邮件、公开注册运营、研究助手用户额度和公网备份恢复，属于上线准备阶段；首版不展示不能工作的“找回密码”按钮。
- 正式部署需配置固定 `FLASK_SECRET_KEY`、HTTPS 和 `SESSION_COOKIE_SECURE=true`，持久保存用户库。代理后的真实客户端限流需要结合可信网关配置；当前账号维度限流已生效，IP 限流在本地代理后是共享的保护上限。
- SQLite 用户数据备份应使用 SQLite backup API 或停服后复制完整数据库。密钥备份与用户库备份分别保管。当前没有自动备份任务。
- 微信小程序仍按原来的免登录阅读流程运行，不与网页账号自动合并。团队共享、项目管理和会员支付未纳入首版。
